DESIGN RULES:
- Flutter mobile app, Android-first.
- Use /UI only as visual inspiration/reference.
- Do NOT copy Pinterest assets, logos, illustrations or exact layouts.
- Create an original, polished, modern health-app UI.
- Avoid generic blue/white AI dashboard aesthetics.
- Use warm, calm, trustworthy visual language.
- Prioritize readability, spacing, accessibility and one-handed mobile use.
- Use reusable design tokens and components.

ENGINEERING RULES:
- Build the MVP in phases.
- Do not generate the entire application in one uncontrolled pass.
- Start with architecture + theme + navigation + onboarding.
- Then cycle tracking.
- Then TTC.
- Then pregnancy.
- Then privacy/partner.
- AI comes after core functionality.
- Core functionality must work without AI and without internet.
- Write tests for date calculations before depending on them in UI.
- Keep business logic separate from presentation.
- Keep medical constants centralized.
- Keep the AI provider abstract so Gemini or OpenAI can be swapped.

MEDICAL SAFETY:
- Never diagnose.
- Never claim an ovulation/fertile-window prediction is exact.
- Never claim pregnancy is guaranteed.
- Never prescribe medication or change a medication dose.
- Never present AI output as a medical diagnosis.
- Use estimate/likely/possible language where appropriate.
- Medical content must be sourced and reviewable.
- If a user reports potentially serious pregnancy symptoms, direct them toward appropriate professional/emergency care instead of diagnosing or reassuring.
- Do not invent medical facts.

AI:
- AI is optional.
- Implement an AIService abstraction.
- Future provider can be Gemini or OpenAI.
- Never put production API secrets directly in the mobile app.
- Send minimum necessary context only.
- Clearly distinguish user-entered facts from app estimates.
- If AI is unavailable, the app must still work normally.

PRIVACY:

- Use app lock.
- Avoid sensitive logs.
- Partner sharing is opt-in.
- Intimacy logs are private by default.
- Provide deletion/export controls.
- Do not expose private wife/partner data to the other partner without explicit permission.
